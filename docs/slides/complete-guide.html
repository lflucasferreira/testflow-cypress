What is Cypress?

Cypress is an end-to-end automation framework that runs tests directly in the browser — no WebDriver, no context switching.

  • Written in JavaScript ou TypeScript
  • Fluent, readable API (cy.visit, cy.get, cy.click)
  • Time-travel debugging, automatic screenshots and videos
  • E2E, Component Testing, and API testing with cy.request
Unlike Selenium/WebDriver, Cypress runs inside the browser and queues commands asynchronously — it does not return Promises and uses chaining (.should()).

Why use Cypress?

⚡ Fast setup

Installation em minutos com npm. Sem drivers externos.

🔍 Visual debug

Interactive runner shows each command and the DOM in real time.

🛡️ Automatic retries

Retries assertions until they pass or timeout.

📦 Ecosystem

Plugins for a11y (cypress-axe), reports, API intercept, and CI.

Installation — step by step

  1. Create or enter the project
    mkdir my-project && cd my-project && npm init -y
  2. Install Cypress
    npm install cypress --save-dev
  3. Open Cypress for the first time
    npx cypress open — scaffolds the cypress/ folder automatically
  4. Install TestFlow Cypress dependencies (optional)
    npm install at the repository root testflow-cypress

Your first test

// cypress/e2e/sign-in.cy.js
describe('Sign In', () => {
  it('should authenticate with valid credentials', () => {
    // Given: user is on sign-in page
    cy.visit('/sign-in')

    // When: user submits valid credentials
    cy.getByHook('email-input').type('user@example.com')
    cy.getByHook('password-input').type('Secret123!', { log: false })
    cy.getByHook('submit-btn').click()

    // Then: dashboard is visible
    cy.url().should('include', '/dashboard')
    cy.getByHook('welcome-message').should('be.visible')
  })
})

Slides convention: data-cy-hook + comando customizado cy.getByHook(). In TestFlow E2E we use data-testid + cy.getByTestId() — see selector-strategy.md.

  statusCode: 401,

// Direct auth — faster than UI

Page Object Model (POM)

Encapsulates selectors, actions, and assertions for each page in a class — specs stay readable and UI changes stay isolated. 

// cypress/pages/SignInPage.js
class SignInPage {
  emailInput()  { return cy.getByHook('email-input') }
  submitBtn()   { return cy.getByHook('submit-btn') }

  visit() {
    cy.visit('/sign-in')
    return this
  }

  signInWith(email, password) {
    this.emailInput().clear().type(email)
    this.passwordInput().clear().type(password, { log: false })
    this.submitBtn().click()
    return this
  }

  shouldReachDashboard() {
    cy.getByHook('page-dashboard').should('exist')
    cy.url().should('include', '/dashboard')
    return this
  }
}

export default new SignInPage()
// cypress/e2e/auth/sign-in.cy.js
import SignInPage from '../../pages/SignInPage'

describe('Authentication', () => {
  beforeEach(() => SignInPage.visit())

  it('signs in via UI and reaches dashboard', () => {
    SignInPage
      .signInWith('user@example.com', 'Secret123!')
      .shouldReachDashboard()
  })
})

cy.session — cached login

before(() => {
  cy.seedAuthToken(user, pass)

  cy.session([user, pass], () => {
    cy.signInViaUI(user, pass)
    cy.url().should('not.include', '/sign-in')
    cy.skipOnboardingTour()
    cy.getByHook('header-profile-btn').should('be.visible')
  }, {
    validate() {
      cy.window().then((win) => {
        const auth = win.sessionStorage.getItem('sandbox-auth')
        if (!auth) throw new Error('Session expired')
      })
    },
    cacheAcrossSpecs: true,
  })
})

beforeEach(() => {
  cy.visitWithSession('/web/dashboard.html')
})

patch vs tryPatch

// patch — expects success (200)
cy.patchUserViaRules(userId, patches)
  .then((res) => {
    expect(res.status).to.eq(200)
  })

// tryPatch — accepts failure
cy.tryPatchUserViaRules(invalidPatches)
  .then((res) => {
    expect(res.status).to.be.oneOf([400, 422])
  })

When to use

  • patch — happy path, full flow
  • tryPatch — negative tests (null field, invalid format)

Best practices to get started

  • Page Objects em cypress/pages/ — selectors, actions, and assertions separated
  • cy.getByHook / cy.getByTestId — single convention, no brittle CSS
  • cy.signInViaAPI ou cy.visitWithSession in beforeEach — faster specs
  • cy.intercept to validate payloads and simulate API errors
  • Fixtures em cypress/fixtures/ — fictional data, no real PII
  • One scenario per it() — easy-to-diagnose failures
  • cy.session + validate() — cached login across specs
  • cy.section / cy.step — readable BDD report in CI
  • Tags com @bahmutov/cy-grep — run only @smoke ou @critical
  • Component tests with cy.mount + E2E for integrated flows
